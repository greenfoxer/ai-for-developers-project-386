# Research #15 (R3): генерация серверных артефактов C# ASP.NET Core из OpenAPI

Тикет: [#15](https://github.com/greenfoxer/ai-for-developers-project-386/issues/15) (wayfinder research, часть #4).
Дата исследования: 2026-10-19. Только факты, решений нет. Первичные источники — GitHub-репозитории инструментов (README/исходные коды generators/шаблоны), npm-registry, NuGet API, официальная документация; URL у каждого факта.
Примечание о методике: сайты `nswag.org`, `openapi-generator.tech` и `typespec.io` на дату проверки отвечают 403 не-браузерным клиентам; их контент 1:1 зеркалируется в репозиториях (`RicoSuter/NSwag` wiki, `OpenAPITools/openapi-generator/docs/*`, `microsoft/typespec/website/src/content/docs/*` + пакетные README) — цитаты взяты оттуда, это первоисточники тех же документов.

TL;DR:

- **NSwag** умеет генерировать серверные артефакты из OpenAPI: `CSharpControllerGenerator` (CLI-команда `openapi2cscontroller`) — MVC-контроллеры + интерфейс + DTO с DataAnnotations; CLI — чистый .NET-инструмент (`dotnet nswag`), официально собран под net8.0/net9.0/**net10.0**; активен (v14.7.1, апрель 2026). Минимальные API не генерирует.
- **OpenAPI Generator** имеет два C#-серверных генератора: `aspnetcore` (MVC-контроллеры, стабильный; поддержка .NET 10 добавлена коммитом от 2026-10-06 в v7.26.0, `aspnetCoreVersion` по умолчанию теперь `10.0`) и `aspnet-fastendpoints` (FastEndpoints; TFM жёстко `net8.0`). Оба генерируют **целый standalone-проект** «с нуля»; боль регенерации реальна (body методов внутри генерируемых файлов) и смягчается `.openapi-generator-ignore` / `--skip-overwrite` / абстрактным «library»-режимом. Требует **Java 11+** (или Docker). Минимальных API нет ни в одном.
- **Microsoft/TypeSpec**: пакета `@typespec/http-api` (как в формулировке тикета) на npm **не существует**. Реальный серверный эмиттер — `@typespec/http-server-csharp`: генерирует MVC-контроллеры + бизнес-интерфейсы + partial-модели с **лучшей защитой ручного кода** из всех (generated-файлы заменяются inline, реализация вне generated/), но статус — «highly experimental», все опубликованные версии alpha (latest 0.58.0-alpha.33), TFM сcaffold-проекта жёстко `net9.0`, валидация — не DataAnnotations, а собственные STJ-converter-атрибуты. **Вход — TypeSpec-исходник, а не OpenAPI-документ**; конвертер OpenAPI→TypeSpec (`tsp-openapi3`) позиционируется как одноразовый помощник, а не часть CI-конвейера.
- Ни один из трёх инструментов **не генерирует ASP.NET Core minimal API** из OpenAPI в production-ready виде (дальше — факты по каждому).

## 1. NSwag

### 1.1 Что генерирует (server-side)

- Позиционирование: «NSwag is a Swagger/OpenAPI 2.0 and 3.0 toolchain … provides tools to generate … client code from these OpenAPI specifications», генерация C#-контроллеров заявлена как отдельный генератор: «**CSharp Controllers** (contract first/schema first development) — CSharpControllerGenerator: Generates Web API Controllers based on an OpenAPI specification (ASP.NET Web API and ASP.NET Core)» — [README](https://github.com/RicoSuter/NSwag/blob/master/README.md), [wiki-страница генератора](https://github.com/RicoSuter/NSwag/wiki/CSharpControllerGenerator).
- Реализация: класс [`CSharpControllerGenerator`](https://github.com/RicoSuter/NSwag/blob/master/src/NSwag.CodeGeneration.CSharp/CSharpControllerGenerator.cs) + [`CSharpControllerGeneratorSettings`](https://github.com/RicoSuter/NSwag/blob/master/src/NSwag.CodeGeneration.CSharp/CSharpControllerGeneratorSettings.cs) в пакете `NSwag.CodeGeneration.CSharp` (наряду с `CSharpClientGenerator`; это единственный C#-серверный генератор проекта, минимальных API нет — в [шаблонах Templates](https://github.com/RicoSuter/NSwag/tree/master/src/NSwag.CodeGeneration.CSharp/Templates) только `Controller.*.liquid` и `Client.*.liquid`).
- Настройки генератора (из исходников):
  - `ControllerTarget`: `AspNet` | `AspNetCore` (по умолчанию `AspNetCore`) — [CSharpControllerTarget.cs](https://github.com/RicoSuter/NSwag/blob/master/src/NSwag.CodeGeneration.CSharp/Models/CSharpControllerTarget.cs), [CSharpControllerGeneratorSettings.cs:25](https://github.com/RicoSuter/NSwag/blob/master/src/NSwag.CodeGeneration.CSharp/CSharpControllerGeneratorSettings.cs#L25).
  - `ControllerStyle`: `Partial` (по умолчанию) | `Abstract` — [там же, строка 24](https://github.com/RicoSuter/NSwag/blob/master/src/NSwag.CodeGeneration.CSharp/CSharpControllerGeneratorSettings.cs#L24), [CSharpControllerStyle.cs](https://github.com/RicoSuter/NSwag/blob/master/src/NSwag.CodeGeneration.CSharp/Models/CSharpControllerStyle.cs).
  - Прочее: `RouteNamingStrategy` (по умолчанию `None`), `UseCancellationToken` (false), `UseActionResultType`, `BasePath`, `ControllerBaseClass` — [CSharpControllerGeneratorSettings.cs](https://github.com/RicoSuter/NSwag/blob/master/src/NSwag.CodeGeneration.CSharp/CSharpControllerGeneratorSettings.cs).
- Что физически в файле-выходе (шаблон [`Controller.liquid`](https://github.com/RicoSuter/NSwag/blob/master/src/NSwag.CodeGeneration.CSharp/Templates/Controller.liquid)):
  - стиль `Partial`: **интерфейс** `public interface I{Class}Controller` (методы `…Async`) + **сгенерированный partial-контроллер** `public partial class {Class}Controller : Microsoft.AspNetCore.Mvc.ControllerBase`, конструктор внедряет `I{Class}Controller implementation`, каждый экшен — `[Http{Get|Post|…}]/[Route("{path}")]` + делегирование в `_implementation`. То есть сгенерированный файл — только маршрутные заглушки-делегаты, бизнес-лог пишется в отдельном классе, реализующем интерфейс → регенерация его не трогает.
  - стиль `Abstract`: `public abstract class {Class}ControllerBase : ControllerBase` с abstract-экшенами (с атрибутами маршрутов/биндинга); реализация — ручные наследники.
  - Биндинг параметров: `[FromQuery]`, `[FromHeader]`, `[FromBody]` (ASP.NET Core); при `GenerateModelValidationAttributes=true` — `[Required]` на обязательных параметрах (по умолчанию `false`, [CSharpControllerGeneratorSettings.cs:27](https://github.com/RicoSuter/NSwag/blob/master/src/NSwag.CodeGeneration.CSharp/CSharpControllerGeneratorSettings.cs#L27)).
  - Опциональная обёртка ответа (`WrapResponse`) генерирует `Task<IActionResult>` с прокидкой status code/headers из client-результата.

### 1.2 DTO и валидация

- DTO генерируются через NJsonSchema (`CSharpGeneratorSettings` вложен в [`CSharpGeneratorBaseSettings`](https://github.com/RicoSuter/NSwag/blob/master/src/NSwag.CodeGeneration.CSharp/CSharpGeneratorBaseSettings.cs) и полностью определяется [NJsonSchema](https://github.com/RicoSuter/NJsonSchema/blob/master/src/NJsonSchema.CodeGeneration.CSharp/CSharpGeneratorSettings.cs)):
  - **DataAnnotations: `GenerateDataAnnotations = true` по умолчанию** («whether to generated data annotation attributes», там же, строки 46/74) — required-свойства → `[Required]` (`RequiredPropertiesMustBeDefined=true` по умолчанию).
  - Nullable: `GenerateNullableReferenceTypes` по умолчанию **false**, `UseRequiredKeyword` (C# 11 `required`) по умолчанию false; `GenerateNativeRecords` (C# 9 records) — по умолчанию false (Poco).
  - Типы дат по умолчанию `System.DateTimeOffset` (`DateType`/`DateTimeType`), `TimeSpan` для time.
  - JSON-библиотека по умолчанию **Newtonsoft.Json**; `SystemTextJson` помечен как «experimental/not complete» (комментарий к `JsonLibrary`); версия STJ `JsonLibraryVersion` по умолчанию 8.0.
- Итого: валидация запросов — классическая MVC DataAnnotations-модель (атрибуты на DTO + `[Required]` на параметрах опционально); FluentValidation из коробки нет.

### 1.3 Поддержка целей/.NET 10

- CLI `NSwag.ConsoleCore`: `TargetFrameworks = net8.0; net9.0; net10.0` — [NSwag.ConsoleCore.csproj](https://github.com/RicoSuter/NSwag/blob/master/src/NSwag.ConsoleCore/NSwag.ConsoleCore.csproj) → инструмент официально собирается и запускается на .NET 10.

## 2. OpenAPI Generator (`aspnetcore`, `aspnet-fastendpoints`)

### 2.1 `aspnetcore` — что генерирует

- Метаданные: generator name `aspnetcore`, stability **STABLE**, type **SERVER**, «Generates an ASP.NET Core Web API server» — [docs/generators/aspnetcore.md](https://github.com/OpenAPITools/openapi-generator/blob/master/docs/generators/aspnetcore.md) (зеркало: [openapi-generator.tech/docs/generators/aspnetcore](https://openapi-generator.tech/docs/generators/aspnetcore), на момент исследования отвечает 403 роботизированным клиентам — поэтому цитируется исходный md репозитория).
- Флейвор: **MVC-контроллеры, не минимальные API**. Шаблон [`controller.mustache`](https://github.com/OpenAPITools/openapi-generator/blob/master/modules/openapi-generator/src/main/resources/aspnetcore/3.0/controller.mustache): `[ApiController] public {classModifier}class {X}Controller : ControllerBase`, экшены `[HttpGet]/[Route("…")]`, `[ValidateModelState]`, `[SwaggerOperation]`/`[ProducesResponseType]`. `classModifier` — только пустая строка или `abstract`; **partial-классы контроллеров не генерируются** (в отличие от моделей: `modelClassModifier` по умолчанию `partial`).
- Выход по умолчанию — **полный standalone-проект/решение**: [`Program.mustache`](https://github.com/OpenAPITools/openapi-generator/blob/master/modules/openapi-generator/src/main/resources/aspnetcore/3.0/Program.mustache) (`CreateHostBuilder … UseStartup<Startup>()`, классический хостинг, слушает `http://0.0.0.0:8080/`), Startup, csproj+`.sln`, Dockerfile, `wwwroot`, appsettings, Filters/OpenApi-разделка — [каталог шаблонов 3.0](https://github.com/OpenAPITools/openapi-generator/tree/master/modules/openapi-generator/src/main/resources/aspnetcore/3.0).
- Режим `buildTarget`: `program` (standalone server, по умолчанию) | `library` — «Generate code for a server abstract class library»; в library-режиме `useSwashbuckle` принудительно false ([docs](https://github.com/OpenAPITools/openapi-generator/blob/master/docs/generators/aspnetcore.md), [AspNetServerCodegen.java](https://github.com/OpenAPITools/openapi-generator/blob/master/modules/openapi-generator/src/main/java/org/openapitools/codegen/languages/AspNetServerCodegen.java)).
- Тело методов (`generateBody=true` по умолчанию) — в том же генерируемом файле: закомментированные `// return StatusCode(…)` + сгенерированный пример JSON и `return new ObjectResult(example)`, либо `throw new NotImplementedException();` ([controller.mustache](https://github.com/OpenAPITools/openapi-generator/blob/master/modules/openapi-generator/src/main/resources/aspnetcore/3.0/controller.mustache)) → **ручная реализация физически живёт в генерируемом файле**.

### 2.2 `aspnetcore` — валидация и зависимости

- Модели: DataAnnotations `[Required]`, `[RegularExpression]`, `[StringLength/Min/MaxLength]`, `[Range]` — [model.mustache:72–78](https://github.com/OpenAPITools/openapi-generator/blob/master/modules/openapi-generator/src/main/resources/aspnetcore/3.0/model.mustache); runtime-enforcement — сгенерированный ActionFilter `ValidateModelStateAttribute`, возвращающий `BadRequestObjectResult` при невалидной модели — [validateModel.mustache](https://github.com/OpenAPITools/openapi-generator/blob/master/modules/openapi-generator/src/main/resources/aspnetcore/3.0/validateModel.mustache).
- Зашитые дефолты пакетов: `useNewtonsoft=true` (по умолчанию Newtonsoft JSON), Swashbuckle по умолчанию `6.4.0` (другие версии в enum помечены deprecated), `Microsoft.Extensions.Configuration.Json`, `JsonSubTypes 1.8.0`, `Microsoft.VisualStudio.Azure.Containers.Tools.Targets`; `nullableReferenceTypes=false` по умолчанию ([docs config options](https://github.com/OpenAPITools/openapi-generator/blob/master/docs/generators/aspnetcore.md), [Project.csproj.mustache](https://github.com/OpenAPITools/openapi-generator/blob/master/modules/openapi-generator/src/main/resources/aspnetcore/3.0/Project.csproj.mustache)).
- Поддержка спецификации генератором (feature set): path/query/header/cookie-параметры ✓; **`allOf`/`anyOf`/`oneOf`/`not` — ✗**, parameter styling ✗, OAuth2 flows ✗ (basic/apikey/bearer ✓) — [docs/generators/aspnetcore.md, FEATURE SET](https://github.com/OpenAPITools/openapi-generator/blob/master/docs/generators/aspnetcore.md).

### 2.3 `aspnetcore` — версии .NET и «pain» регенерации

- Опция `aspnetCoreVersion`: enum `10.0` (по умолчанию), `8.0`, `7.0`, `6.0`, `5.0`, `3.1`, `3.0`, `2.2`, `2.1`, `2.0 (deprecated)`; **значения `9.0` нет** — [docs](https://github.com/OpenAPITools/openapi-generator/blob/master/docs/generators/aspnetcore.md), [AspNetServerCodegen.java:194–204](https://github.com/OpenAPITools/openapi-generator/blob/master/modules/openapi-generator/src/main/java/org/openapitools/codegen/languages/AspNetServerCodegen.java#L194-L204).
- Маппинг TFM: `10.0 → net10.0`, `8.0 → net8.0`, + `useFrameworkReference=true` для обоих — [там же, строки 830–851](https://github.com/OpenAPITools/openapi-generator/blob/master/modules/openapi-generator/src/main/java/org/openapitools/codegen/languages/AspNetServerCodegen.java#L830-L851); флаг `NET_10_OR_LATER` — строка 61.
- Поддержка .NET 10 свежая: `[aspnetcore] Add .NET 10 support for aspnetcore (#25124)` — коммит `f8e224d2db7c` от **2026-10-06**, вошёл в v7.26.0 ([GitHub commits API](https://api.github.com/repos/OpenAPITools/openapi-generator/commits?path=modules/openapi-generator/src/main/resources/aspnetcore)) — т.е. на «current main» всё ок, но за пределами LTS-цикла 9.x кривая выбора версий дырявая (нет 9.0).
- Боль регенерации (факты): генератор пишет целый проект и **перезаписывает файлы при повторном запуске**; официальные механизмы защиты:
  - `.openapi-generator-ignore` (gitignore-подобный) — «allows for better control over overwriting existing files than the `--skip-overwrite` flag», `--ignore-file-override`, `--openapi-generator-ignore-list` — [docs/customization.md](https://github.com/OpenAPITools/openapi-generator/blob/master/docs/customization.md);
  - глобальный `--skip-overwrite` (CLI-флаг `-s | --skip-overwrite`) — [docs/usage.md](https://github.com/OpenAPITools/openapi-generator/blob/master/docs/usage.md#L481);
  - подходы «реализация отдельно от generated»: `classModifier=abstract`/`buildTarget=library` (ручные контроллеры-наследники), `modelClassModifier=partial` (по умолчанию partial), `operationModifier=abstract`.
- Активность 2025–2026: фиксы aspnetcore идут (2026-07-13 remove obsolete wwwroot README; 2026-04-06 abstract-class fix; 2026-10-06 .NET 10) — [commits API по пути aspnetcore](https://api.github.com/repos/OpenAPITools/openapi-generator/commits?path=modules/openapi-generator/src/main/resources/aspnetcore). Релизы проекта примерно ежемесячно: v7.19.0 (2026-01-19) … **v7.26.0 (2026-10-06)** — [GitHub Releases API](https://api.github.com/repos/OpenAPITools/openapi-generator/releases).

### 2.4 `aspnet-fastendpoints`

- Метаданные: STABLE, SERVER, «Generates a server for FastEndpoints (https://fast-endpoints.com/)» — [docs/generators/aspnet-fastendpoints.md](https://github.com/OpenAPITools/openapi-generator/blob/master/docs/generators/aspnet-fastendpoints.md).
- Артефакты: `.sln` + проект; на каждую операцию — класс `{operationId}Endpoint` с `Configure()` (`Verbs(…)`, route, tags, descriptions) и **пустым `HandleAsync()` (комментарии-подсказки)** — [endpoint.mustache](https://github.com/OpenAPITools/openapi-generator/blob/master/modules/openapi-generator/src/main/resources/aspnet-fastendpoints/endpoint.mustache); request/response DTO (классы или records — `useRecords`); модели; `Program.cs` ([templates](https://github.com/OpenAPITools/openapi-generator/tree/master/modules/openapi-generator/src/main/resources/aspnet-fastendpoints)).
- Валидация: `useValidators` → генерируются валидаторы `FastEndpoints.Validator<T>` на **FluentValidation** (`RuleFor(x => x.Param).NotEmpty()` для required) — [request.mustache](https://github.com/OpenAPITools/openapi-generator/blob/master/modules/openapi-generator/src/main/resources/aspnet-fastendpoints/request.mustache); плюс опции `useAuthentication`, `useApiVersioning`, `useProblemDetails`, `useResponseCaching`.
- **TFM жёстко `net8.0`** (не параметризуется; `FastEndpoints`/`FastEndpoints.Swagger` 5.29.0) — [project.csproj.mustache](https://github.com/OpenAPITools/openapi-generator/blob/master/modules/openapi-generator/src/main/resources/aspnet-fastendpoints/project.csproj.mustache). На .NET 10-решение это означает ручной перенос TFM/пакетов после генерации.

Все 144+ версий — `alpha`/`dev`; **ни одной non-alpha публикации за всю историю пакета нет** (данные реестра: oldest 2024-07-31 `0.58.0-alpha.1`).
- Документация пакета помнит статус прямым текстом: «**This package is highly experimental and may be subject to breaking changes and bugs**» — [docs/About Generated Projects (typespec.io)](https://typespec.io/docs/emitters/servers/http-server-csharp/project/) (исходник: [packages/http-server-csharp/docs/usage.md](https://github.com/microsoft/typespec/blob/main/packages/http-server-csharp/docs/usage.md)).
- Смежный клиентский эмиттер: `@typespec/http-client-csharp` (существует, активен) — [npm search](https://registry.npmjs.org/-/v1/search?text=%40typespec%20http).

### 3.2 Что генерирует `@typespec/http-server-csharp`

Из [docs/usage.md «Generated C-Sharp Overview»](https://github.com/microsoft/typespec/blob/main/packages/http-server-csharp/docs/usage.md) и [_About Generated Projects_](https://github.com/microsoft/typespec/blob/main/website/src/content/docs/docs/emitters/servers/http-server-csharp/project.md):

- Структура вывода (`generated/`): **controllers** — «A set of ASP.Net core **MVC controllers**», **lib** — helper-файлы, **models** — request/response + error-модели (наследуют `HttpServiceException`), **operations** — интерфейсы бизнес-логики, которые надо реализовать руками.
- То есть **не минимальные API**: контроллер-снапшот тестов — `[ApiController] public partial class DogsController : ControllerBase`, внедряет `IDogs` через конструктор, экшены `[HttpGet]/[Route("/dogs")]` + `ProducesResponseType`, тело делегирует `DogsImpl.…Async()` — [test/snapshots/sample-service/generated/controllers/DogsController.cs](https://github.com/microsoft/typespec/blob/main/packages/http-server-csharp/test/snapshots/sample-service/generated/controllers/DogsController.cs), генератор: [components/controllers/controllers.tsx](https://github.com/microsoft/typespec/blob/main/packages/http-server-csharp/src/components/controllers/controllers.tsx) (`AspNetMvc.ControllerBase`, `ApiControllerAttribute`).
- **Регенерация — ключевой факт**: файлы `generated/` (models/controllers/operations) «**will be replaced inline to reflect the spec changes, without changing any of your hand-written implementation**»; модели partial («you can add additional members … putting a partial class definition … outside the generated folder»); реализация — отдельные классы, регистрируемые в DI ([usage.md](https://github.com/microsoft/typespec/blob/main/packages/http-server-csharp/docs/usage.md)). Скаффолд-файлы (`ServiceProject.csproj`, `Program.cs`, `appSettings*`, `launchSettings`, `mocks/`) по умолчанию **не перезаписываются** — опция `overwrite` default `false` ([README опции](https://github.com/microsoft/typespec/blob/main/packages/http-server-csharp/README.md)).
- Опции эмиттера: `output-type` (`models|all`), `emit-mocks` (`mocks-and-project-files|mocks-only|none`), `use-swaggerui` + `openapi-path` (SwaggerUI поверх открытого `@typespec/openapi3`), `project-name` (default `ServiceProject`), `http-port`/`https-port`, `collection-type`, `skip-format` — «By default, C# files are formatted using **`dotnet format`**» ([README](https://github.com/microsoft/typespec/blob/main/packages/http-server-csharp/README.md)).
- Валидация: **не DataAnnotations**. Констрейнты TypeSpec (`@minLength/@maxLength/@pattern/@minValue/@maxValue/@minItems…`) материализуются в собственные атрибуты-JsonConverter'ы: `StringConstraint`, `NumericConstraint<T>`, `ArrayConstraint<T>` (класс [`StringConstraintAttribute.cs`](https://github.com/microsoft/typespec/blob/main/packages/http-server-csharp/test/snapshots/sample-service/generated/lib/StringConstraintAttribute.cs): `public class StringConstraint : JsonConverterAttribute` — `StringJsonConverter.Read` бросает `JsonException` при нарушении; карта атрибутов — [src/utils/attributes.tsx](https://github.com/microsoft/typespec/blob/main/packages/http-server-csharp/src/utils/attributes.tsx)); в lib есть также `HttpServiceExceptionFilter.cs`. Документирование: «Controllers **perform validation of input requests**» ([usage.md](https://github.com/microsoft/typespec/blob/main/packages/http-server-csharp/docs/usage.md)).
- TFM скаффолда: `net9.0` зашит в генераторе проекта + пакет `SwashBuckle.AspNetCore 7.3.1` — [src/components/project/csproj.tsx:26](https://github.com/microsoft/typespec/blob/main/packages/http-server-csharp/src/components/project/csproj.tsx#L26); сообщение шаблона `tsp init`: «Generated ASP.Net services require **dotnet 9**» — [packages/compiler/templates/scaffolding.json](https://github.com/microsoft/typespec/blob/main/packages/compiler/templates/scaffolding.json). **net10.0 из коробки нет** (смена одной строки в скаффолде — на факт не тянет как «поддержка»).
- Вход — **TypeSpec-исходник, не OpenAPI-документ**: `tsp compile . --emit=@typespec/http-server-csharp` ([README](https://github.com/microsoft/typespec/blob/main/packages/http-server-csharp/README.md)). Прямой «OpenAPI → сервер» конвейер нет: опция `openapi-path` используется только для SwaggerUI.
- OpenAPI→TypeSpec: `@typespec/openapi3` включает CLI `tsp-openapi3` («converting OpenAPI3 to TypeSpec»), но документация маркирует это как **одноразовую помощь на старте**: «The OpenAPI3 to TypeSpec conversion purpose is a **one time conversion** to help you get started … The output **can change in future versions without being considered a breaking change**» — [docs: OpenAPI3 to TypeSpec](https://github.com/microsoft/typespec/blob/main/website/src/content/docs/docs/emitters/openapi3/cli.md), [package.json bin](https://github.com/microsoft/typespec/blob/main/packages/openapi3/package.json); аналогично VS Code-команда «Import TypeSpec from OpenAPI 3» — [import-from-openapi3.ts](https://github.com/microsoft/typespec/blob/main/packages/typespec-vscode/src/vscode-cmd/import-from-openapi3.ts).
- `tsp init`: встроенный шаблон **«Generic REST API»** предлагает эмиттер `@typespec/http-server-csharp` с подписью «**C# server stubs**» (output `{output-dir}/server/aspnet`) + инструкцию `npx hscs-scaffold . --use-swaggerui --overwrite` ([scaffolding.json](https://github.com/microsoft/typespec/blob/main/packages/compiler/templates/scaffolding.json)). Отдельного «API-first ASP.NET-шаблона с загрузкой OpenAPI» нет (в templates — empty/rest/library-ts/emitter-ts).
- Скаффолд-CLI: бин `hscs-scaffold` из `@typespec/http-server-csharp` (`cmd/hscs.js`), требует **Node >= 22** ([package.json](https://github.com/microsoft/typespec/blob/main/packages/http-server-csharp/package.json)). `emit-mocks "mocks-and-project-files"` позволяет создать проект без `hscs-scaffold` — `tsp compile … --option …emit-mocks=…` ([project.md](https://github.com/microsoft/typespec/blob/main/website/src/content/docs/docs/emitters/servers/http-server-csharp/project.md)).

### 3.3 TypeSpec toolchain и статус

## 6. Implications for this repo (options only)

1. **Конвейер «TypeSpec → OpenAPI → серверный код» сегодня фактически имеет только два полноценных исполнителя последнего шага для ASP.NET Core: NSwag и OpenAPI Generator (`aspnetcore`).** Оба производят MVC-контроллеры, а не минимальные API; «минимальных API» артефактов из OpenAPI в этом списке инструментов нет вообще (в `docs/generators.md` у OG из C#-серверов только `aspnetcore`, `aspnet-fastendpoints`, `csharp-functions`).
2. **NSwag-опция** (вариант A): единственная, не добавляющая в CI ничего кроме dotnet-SDK; низкая боль регенерации по конструкции (partial-контроллер + DI-интерфейс). Факторы риска как факты: OpenAPI 3.1 на входе не заявлен (наш TypeSpec default — 3.1.0; пришлось бы фиксировать `openapi-versions: ["3.0.0"]` на эмиттере или проверять 3.1-handling); валидация DTO — DataAnnotations default-on.
3. **OpenAPI Generator `aspnetcore`-опция** (вариант B): официальный default теперь `net10.0` (с 2026-10-06), DataAnnotations+ActionFilter из коробки; но требует Java/Docker в CI, генерирует монолитный standalone-проект целиком (схлопнуть с существующим проектом можно только выборочным выводом файлов) и тело экшенов живёт в generated-файлах — защита только через `.openapi-generator-ignore`/`--skip-overwrite`/abstract-library режим.
4. **`aspnet-fastendpoints`-опция** (вариант C): ближе всего к «endpoint-per-operation», но TFM hardcode `net8.0`, шаблоны без изменений с 2025-08, и вся ручная работа (body) внутри генерируемого файла.
5. **TypeSpec-эмиттер `@typespec/http-server-csharp`-опция** (вариант D): самая чистая модель разделения сгенерированного и ручного кода (generated/ заменяется inline; реализация — свои классы за интерфейсами; partial-модели; скаффолд не затирается default'ом). Но: это путь **«TypeSpec — source of truth»**, а не «OpenAPI → артефакты» (для OpenAPI-входа предлагается одноразовый `tsp-openapi3` с явной оговоркой про нестабильность); alpha-статус без единого stable-релиза; hardcode `net9.0`; валидация — нестандартные атрибуты вместо DataAnnotations; в CI нужен Node 22+ (или standalone-бинарь с ограничениями) — т.е. два рантайма (Node + dotnet) на generate-шаге.
6. **Отсутствие продукта Microsoft для серверной кодогенерации — факт**: ни `@typespec/http-api` (пакета нет), ни Kiota (клиенты), ни `Microsoft.OpenApi.*` (библиотека, не кодогенератор), ни dotnet-CLI/VS-шаблоны серверных стабов из OpenAPI в learn.microsoft.com (страница команды — 404 на дату проверки). Если конвейер требует «сервер из OpenAPI сегодня, на .NET 10», выбор сужается до NSwag vs OpenAPI Generator; TypeSpec-эмиттер становится релевантен, если спецификация остаётся в TypeSpec, а OpenAPI — лишь артефакт.
7. Риск-факты для любого выбора: версионная поддержка «свежих» TFM у OG дырява (9.0 отсутствует как опция), у NSwag 3.1-вход не документирован, у hscs нет stable-выпуска и есть hardcode net9.0; ни один из инструментов не обещает «production-ready» — везде артефакты = заготовки (NotImplementedException/TODO/делегаты в пустые реализации).
